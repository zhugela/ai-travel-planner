# DESIGN.md — 设计原则与边界

> 本文件回答“为什么这样设计”。具体实现位置见
> [../ARCHITECTURE.md](../ARCHITECTURE.md)。

## 1. 产物优先

旅行助手的目标不是展示模型多会聊天，而是产出可执行方案：

- 行程必须能按天阅读。
- 预算必须能拆解。
- 不确定信息必须进入 `assumptions`。
- RAG 无命中必须明确拒绝，而不是编造。

## 2. Harness 与模型分工

- 模型负责推理、措辞和提出工具意图。
- 代码负责状态、权限、停止条件、超时和协议。
- Prompt 是体验约束，不是安全边界。
- 外部输入和工具输出都不能提升为系统指令。

## 3. 状态唯一来源

- 当前实现和约定：仓库文档与代码。
- 当前功能边界：`feature_list.json`。
- 本轮进度与 blocker：`claude-progress.md`。
- 会话交接：`session-handoff.md`。
- 聊天上下文只用于协作，不作为可恢复状态。

## 4. 明确失败

- RAG 无命中返回固定兜底。
- SSE 以 `done` 明确结束。
- Agent 达到步数上限或死循环时置 `ERROR` 并发送 `loop` / `error`。
- 工具缺少依赖时不注册，模型不得用其他工具假装完成。
- 测试失败必须保留失败事实，不把旧结果当当前通过。

## 5. 机械约束优先

能用代码、测试或脚本保证的事情，不只写在提示词里：

- 功能清单最多一个 `in_progress`。
- `passing` 必须有 evidence。
- 高风险路径必须经过统一解析器。
- SSE 事件名由契约测试验证。
- 收尾由检查清单和脚本共同约束。

## 6. 当前非目标

- 不引入数据库和分布式会话。
- 不做真实多租户登录体系，除非进入生产化任务。
- 不追求“万能 Agent”；优先专用、可校验的工具。
- 不将 docs 自动灌入运行时 RAG；运行时知识库仍位于
  `src/main/resources/document/`。
