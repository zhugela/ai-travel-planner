# PRODUCT_SENSE.md — 产品判断

## 1. 核心用户

### 自由行用户

需要从零散信息得到一个能执行的行程，关心时间、预算、同行人和节奏。

### 学习型开发者

需要看清 Spring AI、RAG、工具调用、Agent 和 SSE 如何组合，而不只是看到一个聊天框。

## 2. 核心价值

产品价值不是“能回答旅行问题”，而是：

- 把模糊需求转成有结构的方案。
- 对资料范围有边界，没命中就承认。
- 复杂任务能展示过程，并能被停止。
- 结果可继续编辑、下载或作为行程底稿。

## 3. 默认产品原则

1. **先给可执行结果，再解释**：行程、预算、假设优先。
2. **不确定就显式写出**：用 `assumptions`，不要假装知道人数、日期和预算。
3. **知识库边界可见**：RAG 未命中不是故障。
4. **长任务有过程**：Agent 必须显示步骤和结束状态。
5. **失败有下一步**：错误提示应告诉用户换问题、补信息或稍后重试。
6. **高风险能力默认收敛**：终端、任意文件访问和内网请求不是普通旅行能力。

## 4. 当前 MVP

| 能力 | 状态假设 | 产品边界 |
|---|---|---|
| 普通问答 | 已有实现和人工证据 | 支持会话 ID 续聊，无登录 |
| 结构化报告 | 已有实现和人工证据 | 信息缺失时假设补齐 |
| 本地 RAG | 已有实现和人工证据 | 仅覆盖本地攻略文档 |
| Agent 工具流 | 主链路已有实现和人工证据 | 工具安全边界仍不完整 |
| 多模态 | 未交付 | 不作为当前承诺 |
| 生产部署 | 未验证 | 不承诺高可用、多租户或计费 |

## 5. 需求优先级

1. 恢复可信测试基线。
2. 修复文件、终端和网络工具的安全边界。
3. 完成 Vue 前端四层验收。
4. 验证 Docker 构建与启动。
5. 增加可观测性：traceId、检索耗时、工具调用状态。
6. 生产化前增加鉴权、额度、限流和会话归属。

## 6. 非目标

- 不追求覆盖全球实时价格和库存。
- 不在没有安全设计时开放通用终端。
- 不用“更长 Prompt”代替权限控制。
- 不把学习笔记原文直接当作运行时知识库。
