# QUALITY_SCORE.md — 质量评分标准

> 本文件定义“怎样算好”。当前代码库的逐轮快照见
> [../quality-document.md](../quality-document.md)。
> 最后更新：2026-11-12

## 1. 评分范围

每个产品领域和架构层按 0–2 分评价：

- **0 缺失**：没有实现、没有验证，或边界明显不安全。
- **1 部分可用**：主路径存在，但证据、测试或边界不完整。
- **2 健康**：行为、自动化验证、错误路径和维护文档完整。

## 2. 产品领域标准

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| 行为验证 | 只存在于代码或描述 | 有人工主路径证据 | 自动测试覆盖主路径和关键边界 |
| Agent 可读性 | 需要口头解释 | 有名称和局部文档 | 入口、边界、契约和失败路径可追踪 |
| 测试稳定性 | 无测试或长期红灯 | 测试存在但依赖真实外部服务 | 默认 mock/隔离，失败可定位 |
| 错误处理 | 空响应、堆栈或静默失败 | 有兜底但未全部验证 | 用户可见错误、日志和协议一致 |
| 安全边界 | 用户/模型输入直达系统操作 | 有局部校验 | 统一校验、默认拒绝、审计和测试 |

## 3. 架构层标准

### API 层

- 请求字段、内容和长度校验。
- 统一错误响应，不泄露堆栈和密钥。
- SSE 协议和生命周期有测试。
- 修改接口同步 `API_CONTRACT.md`。

### Application / Agent 层

- 状态转换明确。
- 有最大步数、超时和循环终止。
- 工具结果被回填到模型历史。
- `done` 在所有结束路径都可观察。

### RAG 层

- 知识库来源可追踪。
- 无命中时不调用生成模型。
- 检索参数、耗时和命中数可观测。
- 隐私边界描述准确。

### Tools 层

- 能力注册前检查依赖。
- 参数由代码校验，不由 Prompt 保证。
- 文件、URL、命令和输出大小有硬边界。
- 高风险能力默认关闭。

### Persistence / Config 层

- 会话 ID 和文件名经过安全解析。
- 并发写有策略。
- 密钥通过环境变量注入。
- 生产不开启 DEBUG。

## 4. 合并门槛

一个功能要进入 `passing`，至少应满足：

- 目标行为有自动化或明确的人工证据。
- 关键失败路径已验证。
- 没有新增 P0 安全债。
- 文档与实现一致。
- 下一轮可以从仓库状态继续。

## 5. 定期更新

在以下时机更新 `quality-document.md`：

- 完成重要功能或安全修复后。
- 做完清理、重构或 Harness 简化实验后。
- 切换模型、Embedding 方案或部署方式后。
- 准备对外演示或写简历之前。
