# SECURITY.md — 安全边界

> 当前是单人学习项目，不是安全的生产系统。本文区分“已采用”“未完成”和“上线前必须”。

## 1. 威胁模型

| 风险源 | 典型问题 | 第一道边界 |
|---|---|---|
| 用户输入 | 超长内容、路径穿越、SSRF、提示注入 | 输入校验和协议限制 |
| 模型输出 | 错误工具参数、编造执行结果 | 代码重新校验，不信任模型 |
| 工具结果 | 恶意网页、文件内容注入 | 内容隔离、大小限制、输出转义 |
| 会话 ID | 猜测/覆盖其他会话 | 服务端身份与归属校验 |
| 密钥 | 被写入脚本、日志、Git | 环境变量和忽略文件 |
| MCP / 外部服务 | 越权工具、内网访问 | 本地工具注册和网络策略 |

## 2. 硬规则

- API Key 只从环境变量读取。
- 不提交 `.env`、本地启动脚本、运行日志和包含密钥的截图。
- 文件最终访问路径必须位于授权根目录。
- URL 工具只允许 `http/https`，并阻止 loopback、私网和云元数据地址。
- 通用终端不得仅靠首命令白名单；优先移除或放入隔离沙箱。
- 不可用的工具不注册给模型。
- 生产关闭 DEBUG、匿名 Swagger/Knife4j 和宽泛 CORS。
- 错误响应不返回堆栈、主机绝对路径和第三方完整响应。

## 3. 已采用

- 搜索工具基于 `health()` 做能力门控。
- Agent 每次请求新建实例，隔离 message 列表。
- 终端工具检查首个命令词。
- Agent SSE 有步数上限、LoopGuard 和显式结束信号。
- 密钥配置使用环境变量占位符。

## 4. 未完成

| 风险 | 当前问题 | 验收条件 |
|---|---|---|
| 文件路径 | `FileOperationTool` 等直接拼接用户输入 | 统一安全路径解析器与越界测试 |
| 终端 | `cmd /c` / `bash -c` 解释整段命令 | 默认关闭或结构化参数 + 沙箱 |
| SSRF | 抓取/下载边界不完整 | 解析后 IP、重定向、端口、大小和超时校验 |
| 鉴权 | 业务 API 无登录 | 401、会话归属、用户级配额 |
| 限流 | 无频率/并发上限 | SSE 并发、请求频率和模型额度 |
| 审计 | 无 traceId 和工具级审计 | 结构化、脱敏、可关联 |

## 5. 密钥事故处理

1. 立即停止继续使用和传播该密钥。
2. 在供应商后台作废并生成新密钥。
3. 检查 Git 历史、日志、截图和构建产物。
4. 清理范围要覆盖本地脚本、Shell/PowerShell 历史和 CI 日志。
5. 新密钥只放入被忽略的本地环境文件或密钥服务。
6. 记录“事故已处理”而不是记录密钥本身。

## 6. 合并前安全检查

- [ ] 没有新增明文密钥。
- [ ] 没有扩大文件、终端、网络工具的默认权限。
- [ ] 用户输入没有直接变成系统命令或路径。
- [ ] 模型输出没有绕过代码校验。
- [ ] 新增外部请求有超时、大小和重定向限制。
- [ ] 日志不记录完整 Prompt、回答、文件和身份信息。
