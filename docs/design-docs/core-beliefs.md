# 核心设计信念

## 1. 结果比对话更有价值

旅行助手要交付行程、预算、假设和注意事项。聊天只是交互方式。

## 2. 模型不拥有权限

模型可以提出文件、网络和终端操作意图，但代码必须重新校验参数、权限和边界。

## 3. 停止条件必须显式

Agent 必须有最大步数、循环检测、超时和结束事件。不能依赖模型“自觉停止”。

## 4. 没有证据就没有完成

代码存在、接口返回 200、旧截图和口头描述都不等于当前功能通过。证据必须能重跑。

## 5. 仓库是记忆

设计理由、计划、测试边界、已知风险和技术债都进入仓库，减少对聊天记录和个人记忆的依赖。

## 6. 短入口、深链接

根入口只保留路由、硬约束和完成定义。具体规则放到可维护的 `docs/` 页面。

## 7. 机械约束优先

能用测试、schema、脚本或类型边界保证的规则，不应只靠 Prompt 或“请注意”。

## 8. 清理是常规工作

发现重复文档、过期状态和多余 Harness 组件时，先记录假设，再小步移除和验证。
