# F-001 — 恢复可重复的测试基线

## 目标

让维护者可以从当前工作区运行标准测试，得到可信的 passed / failed / skipped，
并明确失败来自代码、环境还是测试隔离问题。

## 用户可见行为

开发者运行 `.\mvnw.cmd test` 后，不需要人工猜测哪些测试真的跑了；失败类、原因和
下一步修复对象都能从输出与仓库文档找到。

## 范围

包括：

- 运行完整测试。
- 修复测试配置、隔离和因文档/实现不一致导致的失败。
- 记录测试统计和失败原因。

不包括：

- 新增大功能。
- 顺手重写文件工具和终端工具。
- 前端联调和 Docker 部署。

## 已知风险

- 测试可能依赖真实 DeepSeek、本地 ONNX 模型或 Windows 本地路径。
- 旧 `target/surefire-reports` 只能证明过去某次执行，不是当前证据。
- 上层 Git 仓库混有多个项目，提交必须精确暂存。

## 测试先行

1. 先运行全量测试，保存失败堆栈摘要。
2. 对每个失败，判断是测试隔离、实现缺陷还是过期断言。
3. 若是实现缺陷，先补最小回归测试。
4. 若是测试隔离，修复测试配置并证明不依赖真实付费 API。

## 验证证据

必须记录：

- 命令和 JDK/Maven 版本。
- passed / failed / skipped 数量。
- 失败类名与第一条根因。
- 修复后同一命令的输出。

写入 `claude-progress.md` 和
[../../project/TEST_CASES.md](../../project/TEST_CASES.md)。

## 完成条件

- [ ] `scripts/check-harness.ps1` 通过。
- [ ] 全量测试结果已记录。
- [ ] 所有失败都有分类和归属。
- [ ] 不依赖真实 API Key 的测试默认可重复运行。
- [ ] 仍未修复的内容进入技术债，不被隐藏。
