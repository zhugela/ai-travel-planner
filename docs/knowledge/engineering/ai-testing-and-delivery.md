# AI 应用测试与交付

> 状态:方法已采用,自动化覆盖待补
> 来源:前后端联调、Prompt 事故复盘与验收清单
> 最后验证:2026-11-10

## 核心结论

AI 应用不能只断言“HTTP 200”或“返回非空”。需要同时验证确定性代码、接口契约、模型行为边界和真实页面体验。

## 四层交付门禁

| 层 | 验证目标 | 典型失败 |
|---|---|---|
| 1. 连通 | 服务、状态码、Content-Type | 接口未启动、路由错误 |
| 2. 契约 | 字段、事件名、结束语义 | 前后端字段或 SSE 事件不一致 |
| 3. 渲染 | 空态、错误态、长内容、重复请求 | 页面白屏、流被拆碎、自动重连 |
| 4. 体验 | 真实任务、移动端、停止与重试 | 能用但不可演示或无法恢复 |

任何一层失败都不能宣称功能完成。详细项目验收步骤见 `docs/guides/ACCEPTANCE_CHECKLIST.md`。

## 分层测试策略

### 单元测试:不调用真实模型和公网

优先覆盖:
- 路径、URL、命令、输入长度等边界校验。
- Agent 状态机、循环保护和错误映射。
- RAG 切片、过滤、重排和无命中逻辑。
- Prompt 选择与结构化输出解析。

ChatModel、EmbeddingModel、HTTP 客户端和时钟使用 Mock/Fake,保证快速、可重复、无费用。

### 契约/集成测试:验证框架接线

- Controller 的状态码、JSON Schema、SSE Content-Type 与事件顺序。
- Spring Bean 装配、不同 profile 和缺配置启动行为。
- 本地向量模型加载和小型固定知识库检索。
- 客户端断连、超时和取消后资源释放。

### 模型评测:验证行为而非精确措辞

固定一小组代表性样本,断言:
- 应该拒答时没有编造。
- 结构化报告字段齐全、天数和预算约束成立。
- Agent 工具不可用时明确说明能力边界。
- RAG 回答可追溯到证据。

不要用整段字符串完全相等判断开放式回答。使用结构约束、关键事实和评分规则。

### 端到端测试:少而关键

保留少量真实模型用例验证主链路,并设置预算、超时和重试上限。失败时区分代码失败、供应商失败和评测波动。

## 安全回归必测

- 密钥缺失和日志脱敏。
- `../`、绝对路径、符号链接逃逸。
- shell 连接符、重定向和子命令。
- 私网/元数据 URL、重定向 SSRF、大响应体。
- 未认证、越权会话、超长输入、超并发和限流。
- SSE 断连后任务取消与配额释放。

## 完成交付格式

每次任务至少报告:

```text
✅ 改了什么
✅ 测试:通过 / 失败 / 跳过,附可复现命令或证据
✅ 文档:更新了哪些规范、契约或 ADR
⚠️ 已知问题:影响与下一步
↩️ 回退:commit 或明确回退方式
```
