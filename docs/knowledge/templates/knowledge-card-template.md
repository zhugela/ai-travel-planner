# 知识卡片模板

> 复制本页后删除提示语。文件名使用小写英文和连字符,放入最合适的分类目录。

```markdown
# 标题:一句话说清问题

> 状态:提议 / 部分采用 / 已采用
> 来源:项目、事故或需求
> 最后验证:YYYY-MM-DD

## 问题

用户可见现象是什么?不要先写技术猜测。

## 根因

写可验证的根因和证据。无法确认时明确写“待验证”。

## 可复用规则

- 规则必须能指导行动。
- 避免只写“注意安全”“加强测试”这类空话。

## 实施清单

- [ ] 最小改动
- [ ] 异常路径
- [ ] 监控或日志
- [ ] 回退方式

## 验收方法

给出正向、反向、边界三个可重复验证的用例。

## 适用边界

说明哪些技术栈、场景或规模下不适用。

## 项目证据

- `path/to/source`
- `path/to/test`

## Related

- [[category/related-page]]
```

完成标准:
- 结论与当前实现事实分开写。
- 至少有一个可重复的验收方法。
- 至少有一个来源或项目证据。
- 至少链接一个相关页面。
