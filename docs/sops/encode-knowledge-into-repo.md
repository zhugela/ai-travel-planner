# SOP：把不可见知识写进仓库

## 触发条件

- 问题反复出现，但只存在于聊天或某个人记忆里。
- 修复依赖特定环境、供应商行为或历史决策。
- 新 Agent 容易踩同一个坑。
- 规则已经口头说过多次。

## 步骤

### 1. 先写事件，不先写结论

记录：

- 触发条件。
- 可观察症状。
- 实际根因或当前最可信假设。
- 影响范围。
- 证据链接/类名/日志片段（脱敏）。

### 2. 判断知识类型

| 类型 | 写入位置 |
|---|---|
| 当前项目规则 | `docs/guides/`、`docs/project/` |
| 可跨项目复用 | `docs/knowledge/` |
| 重要取舍 | `docs/adr/` |
| 可重复操作流程 | `docs/sops/` |
| 当前任务状态 | `feature_list.json`、`claude-progress.md` |

### 3. 写成可执行规则

避免“注意安全”“小心并发”。改成：

- 什么输入必须拒绝。
- 哪条命令可以验证。
- 通过/失败标准是什么。
- 触发条件变化后应回退到哪里。

### 4. 加一条深链接

从最接近工作流的入口链接过去：

- 根规则链接到 `SECURITY/ARCHITECTURE`。
- 架构文档链接到 ADR。
- 知识索引链接到卡片。
- Prompt 规则链接到测试或验收清单。

保持根入口短，不在 `AGENTS.md` 复制全文。

### 5. 验证文档真实性

- 路径存在。
- 类名、端点和命令属于当前仓库。
- 状态明确区分“已采用/部分采用/提议”。
- 没有把旧日报或未运行测试当作当前证据。

### 6. 定期清理

每次重要变更后检查：

- 是否出现两份互相矛盾的事实来源。
- 旧文档是否应归档。
- 规则是否能被测试或脚本机械执行。
